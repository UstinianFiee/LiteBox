# 数据库宽表显示修复 / Database grid layout fix

日期：2026-09-30。仅源码修复；没有重新打包、发布 Release 或修改用户应用数据。

## 原因与修复

原先结果表 `table-layout: fixed` 配合 `width: 100%`，强制将所有列塞进工作区。
字段很多时，单元格最小宽度不能按预期生效，`overflow-wrap: anywhere` 将内容逐字换行。

- 改为自动列布局和内容宽度，表格至少铺满容器，超宽部分在结果区横向滚动。
- 数据列最小宽度 144px；长文本在有可读宽度的单元格中换行，不删除或截断原始值。
- 保留表头吸顶、行号、分页、完整复制/导出以及蓝白和深色主题。
- 查询结果与表结构共用 `DatabaseResultTable.vue`；不修改数据库驱动、SQL 或连接配置。

## 验证方式

1. 项目根目录运行 `npm run dev:web`，已有 5173 服务时无需重复启动。
2. 打开 `http://127.0.0.1:5173/`，进入数据库连接，点击“查看示例”。
3. 打开 `http://127.0.0.1:5173/tests/fixtures/database-grid.html`，点击“运行布局回归”。
4. 确认报告 `passed: true`、`failures: []`；切换深色主题后再运行一次。
5. 专项页使用生产表格组件和样式，覆盖 3/120 列、50 行、320–1440px 容器宽度、
   完整长文本、空结果、跨页行号、末列可达性、表头吸顶与页面外溢。测试数据全部虚构。
6. 运行 `npm test`、`npm run test:backend`、`npm run build`。
7. 运行 `npm run test:desktop`：使用独立临时数据目录和本地 SQLite，验证真实 SQL 的
   120 列结果在 1440×960、980×740、820×680 下的布局，同时执行已有复制、分页等回归。

浏览器预览不连接真实数据库；真实数据库验证使用 `npm run dev`，不需要打包。
已有 EXE/ZIP 不会自动获得此修复，需另行明确要求重新打包。

## 补充：状态栏下方空白 / Blank area below the status bar

紧凑分页栏的统计文字为无障碍访问保留，通过绝对定位和裁剪隐藏。
原先分页容器没有定位上下文，隐藏文字落在文档坐标系中；对象列表位置较低时，
它会绕过内部滚动容器撑大整个文档，产生第二条滚动条和状态栏下方的空白。

- 分页栏增加相对定位；隐藏文字固定在分页栏左上角，保留 `aria-live` 播报。
- 不通过全局 `overflow: hidden` 掩盖问题，不改变查询、连接、分页和数据存储。
- 小窗口/增大编辑器后，内容仍在主内容区和表格中滚动，底部状态栏留在窗口底部。
- 桌面回归覆盖浅/深主题、1440×960、1280×720、980×640、820×680，
  编辑器最小/最大高度，以及主内容区顶部/底部，共 32 组滚动边界断言。
- 手动检查：查看数据库示例，拖大编辑器，滚到内容底部；确认状态栏下没有空白，
  结果分页栏和对象列表末项可达，主窗口没有额外的纵向滚动条。
