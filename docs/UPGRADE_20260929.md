# V1.0.0 · 2026-09-29 R2 使用与迁移说明

本次保持 V1.0.0 正式版；R2 是构建批次，不是另一个产品版本。源码、浏览器和未打包桌面先验证，再生成免安装 EXE/ZIP。GitHub 推送等待提供仓库地址。

## 1. 工作台、滚动和自适应

- Banner 自动动画可暂停/继续；切换工具、切回窗口、页面恢复后恢复应运行的动画，不覆盖用户主动暂停。系统“减少动态效果”仍优先。
- 滚动条闲置隐藏，悬停或键盘聚焦时可见，滚轮/触控板/键盘滚动不受影响。
- 远程与数据库区域底部对齐；小窗口允许堆叠/内部滚动，不用缩小字号强行挤入。

## 2. 数据库分页与分隔栏

连接后对象树、表结构、查询结果均使用分页；默认50条，可选25/50/100/200。修改查询、对象或每页数量会重置对应分页。库表名称和记录字段完整展示，不再省略长文本。普通字段原样保留，二进制用 base64 表示。

- 拖动对象列表右侧分隔条调整宽度；拖动查询编辑器下方分隔条调整编辑器/结果高度。聚焦分隔条后可用方向键，Home/End 切至界限。窄窗口侧栏改为上下排列。
- 查询结果未知总数时显示当前页及下一页，不伪造总行数。**复制/导出仅当前页**，按钮附近有提示，不等同全库导出。
- SQL 中自己填写的 LIMIT/FETCH/TOP 仍然有效；内置虚构 demo 的 LIMIT 200 只是演示。
- 每页有约2MiB软内存界限，可能少于指定条数，下一页按实际读取行数续接。第一条较大记录完整保留；单条超过32MiB显式提示选择更少字段，不悄悄截断。
- 分页重新执行只读查询、跳过已读行，不维持跨页事务快照。建议 `ORDER BY` 唯一且稳定的字段；并发修改可能导致跨页变化。很深的页仍需扫描前面的记录，建议查询增加范围条件。
- Redis 使用 SCAN 分批读取，支持 MATCH/TYPE/COUNT；其扫描本身不保证并发修改时的快照或唯一性。结构化写入仍须确认，不开放任意写SQL或任意Redis管理命令。

## 3. SSH 复制、粘贴和 AI 分析

选中终端文本后使用工具栏或右键菜单；快捷键 `Ctrl+Shift+C` 复制、`Ctrl+Shift+V` 粘贴。含换行或控制字符的粘贴会提示可能执行命令，先核对再确认。单次粘贴上限64K字符。

右键“发送到AI分析（草稿）”把选中的错误文本放入报错分析草稿，**不自动发送给服务商、不执行修复命令**。已有待处理草稿会优先保留。发送前自行删除令牌、密码、内部地址等敏感内容。切换 AI 页面不应断开 SSH。

终端为16色 ANSI 主题调色板；颜色取决于服务端输出，不会把任意无色文本自动理解为语义高亮。菜单支持方向键/Escape，Shift+F10 可打开键盘菜单。上述功能针对内嵌 SSH；Windows RDP 在系统远程桌面窗口使用其自身复制/粘贴策略。

## 4. AI 附件与常用记录

点击“添加图片 / 附件”，选择、预览或移除后发送。发送附件前有确认；它们仅发到设置中保存的模型服务。浏览器只预览，真实请求及磁盘附件存储需桌面版。

| 类型         | 支持与限制                                                                                                    |
| ------------ | ------------------------------------------------------------------------------------------------------------- |
| 图片         | PNG、JPEG、WebP、GIF，单个≤6MiB；服务商/模型必须支持 OpenAI-compatible image_url，动画GIF的实际处理由模型决定 |
| 文本         | UTF-8 txt/md/log/json/csv/tsv/sql/yaml/yml/xml/ini/conf，单个≤512KiB                                          |
| 单条消息     | 最多5个附件，总计≤12MiB；长对话有总上下文上限，超限显式报错并提示新建会话                                     |
| 尚不支持     | PDF、Word、Excel二进制内容解析，须先转换为文本/截图；非UTF-8日志先转码                                        |
| 本地附件目录 | litebox-data/ai-attachments，默认容量上限256MiB；删除会话不自动删除文件，避免误删其他引用                     |

在“常用片段”维护标题与正文。提问时主动勾选“参考常用记录”进行本地关键词相关性检索，默认不勾选。可预览并逐条排除，最多3条、每条最多6000字符。只有选中的摘录随该轮提问提交，不上传整个片段库。聊天保留来源快照以便回看；模型仍可能遗漏引用或回答错误，需要核实。

这是轻量本地检索，不是向量数据库或自动联网知识库。附件/片段中的指令按不可信资料处理；提示词防护并不能保证模型绝不会受提示注入影响。不要上传秘密。历史消息中的附件与引用可能随同一会话的后续问题再次发给同一服务商；要彻底停止引用旧上下文，请开启新对话。

尚未发送的附件队列只属于当前页面，切换功能前先处理；已发送附件与会话引用会保存。Markdown导出是聊天正文，不打包附件。

## 5. 历史日志

默认每页50条，可选25/50/100/200；筛选会重置到第一页。分页展示全部仍在保留期内的记录，不把分页当作删除。原先最多3000条的存储上限不变，超过上限会轮换旧记录。只记录动作元数据，不记录终端/SQL/聊天正文和密码。

## 6. 保留及迁移应用数据

1. 保存工作并正常退出新旧 LiteBox。先备份要使用的数据目录，不修改原目录。
2. **完整迁移推荐复制整个一个 litebox-data 到新 EXE 同级目录**，包括 state.json、ai-attachments、凭据密文和日志；不要盲目合并多个来源，也不要覆盖未经备份的新目录。
3. 设置中的 JSON 备份包含配置、文档、对话及附件引用，**不含附件原文件、API Key、远程/数据库密码或私钥**。只恢复 JSON 不能恢复图片内容；必须保留对应 ai-attachments 目录。
4. 密码/密钥使用当前Windows账号系统加密，复制到其他电脑/账号不保证能解密，需要重新填写。
5. 旧包清理仅删除核对过的程序文件；任意位置的 litebox-data、.litebox-data、legacy-data-v1.0.0、未知用户文件与备份保留。新包不会自动导入/合并旧数据。
6. 不上传 release、artifacts、数据目录或附件到GitHub。只上传正式EXE、ZIP与SHA256SUMS.txt作为Release附件。

## English summary

R2 adds resilient banner motion, accessible auto-hiding scrollbars, responsive aligned panes, paged database/history views, draggable keyboard-accessible dividers, guarded SSH clipboard operations and selection-to-AI drafts. AI supports selected images and UTF-8 text attachments, plus opt-in local retrieval of up to three saved snippets. Requests go only to the configured provider; visual models are required for images. Copy/export covers the current database page. Query pagination reexecutes queries and is not a snapshot. Preserve the complete data directory, including ai-attachments; JSON backup alone does not include binary attachments or credentials. Existing encrypted secrets require the original Windows account. No GitHub push is performed in this update.
